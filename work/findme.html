01 · Problem

Every sprint added a slightly different button

New screens shipped fast, and small drift crept in: a new spacing value, the same pattern solved twice.

Drift slows engineers down and makes a product feel stitched together. FindMe was growing faster than its system.

02 · Goals

What it had to do

  • Goal 01

    Findable

    Engineers can find the right component by name.

  • Goal 02

    Complete

    Every state is defined, so nothing is guessed.

  • Goal 03

    Consistent

    Two products share one library.

03 · Solutions

Three habits that kept 2 products consistent

Solution 01

Name components the way engineers search

Every name follows one pattern, Button / Primary / Medium / Default, so the library is easy to navigate.

Every handoff used library names

Solution 02

Define every variant and state

Default, hover, focus, disabled and loading are all designed, so built screens match designed ones.

Worked with developers until built matched designed

Solution 03

Design inside the sprint, not ahead of it

Joining backlog refinement and sprint planning meant design questions came up while they were cheap to answer.

04 · Research and design

Research that fed straight into the wireframes

I supported 12+ user interviews and usability tests in Maze, tagged findings in Dovetail, and fed them straight into the wireframes.

05 · Reflection and outcome

A library nobody can find doesn't get used

Naming and states mattered as much as how the components looked.
