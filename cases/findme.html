The short version

The problem

A product growing faster than its system

New screens every sprint meant small drift: a slightly different button, a new spacing value, the same pattern solved twice.

What I did

Two tracks at once

Added reusable components, patterns and visual standards to the library, and designed features from research to delivered UI.

The result

Consistency from the library

When a feature needed a card, a form or a list, the answer already existed. Outcome numbers are being confirmed and will be added here.

How I worked

Three things, every sprint

01

Design system: components, patterns and standards

I added components, interaction patterns and visual standards to FindMe's Figma library, each with its variants and states defined, so new features started from the library instead of from scratch.

  • Clear, consistent naming, because a library engineers can't navigate doesn't get used.
  • Variants and states defined for each component, so nothing was left to guess.

02

Feature design: from discovery to delivered UI

Research first, then wireframes, then interactive prototypes, then the final UI, all in Figma. Every screen was responsive from the first wireframe, so the phone layout was a decision, not an afterthought.

03

Working with engineering: inside the sprint

I joined backlog refinement and sprint planning with engineering and product, so design questions came up while they were still cheap to answer.

  • Handoff named components by their library names and spelled out every state.
  • I worked through implementation with the developers, so shipped screens matched designed ones.
