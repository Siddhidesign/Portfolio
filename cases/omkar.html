The same site, rebuilt in code you can read

I don't have the 2022 code anymore, so in 2026 I rebuilt the site from the designer's Figma files with Next.js 16, React 19 and TypeScript. I planned and directed the build, reviewed the code and tested every page; an AI coding assistant wrote much of the code.

Pick a note to see that code running in the live preview.

  1. 1
    Accessibility

    A menu built on a native <dialog>

    showModal() traps focus, Esc closes it and the page behind it goes inert, with no extra library. The close button gets focus first.

  2. 2
    Forms

    Checked in the browser, then on the server

    An invalid form stops before sending and focus jumps to the first problem. The same rules in lib/forms.ts run again on the server.

  3. 3
    Accessibility

    Every error is tied to its field

    aria-invalid and aria-describedby link each message to its input, so a screen reader reads the error with the field.

  4. 4
    Works without JavaScript

    An FAQ on native <details>

    The browser handles the keyboard and screen readers. Answers that share a name open one at a time.

  5. 5
    SEO

    Ready for search engines

    Each page gets a title, description and canonical URL, the home page adds structured business data, and the sitemap and robots.txt are generated at build time.

  6. 6
    Responsive

    Design tokens from the Figma file

    Colors, type and spacing are CSS variables. Spacing steps down at 1100px and 768px, between the 1440px desktop and 390px phone frames.

The work

From the factory floor to the browser

01

Context: a manufacturer's shop window

Omkar Labels has made labels since 1999, in two factories: one in Thane, near Mumbai, and one in Narmadapuram, Madhya Pradesh. Every order passes a four-point quality check, and the company holds OEKO-TEX, FSC and Global Recycled Standard certifications.

The website is where buyers check all of that before picking up the phone.

02

The build: from design file to working page

The designer made the interface; I made it work. Responsive layouts in HTML and CSS, behavior in JavaScript and jQuery, and Bootstrap's grid so pages held together on every screen, all inside WordPress.

I also kept the product pages for a catalog of 50+ products accurate as things changed. The photos here are the kinds of products those pages carried.

03

Working with the designer: where designs meet reality

  • When the design file and the browser didn't match, I raised it early and we solved it together before release.
  • When a layout broke in one browser and not another, I traced the cause in Chrome DevTools and fixed the code, not the symptom.
